# Prompt Templates

All prompt templates used in the cross-review workflow.

> **重要**：所有发给外部模型的 prompt 末尾必须附带"输出格式硬约束"（见 SKILL.md "输出契约"章节）。以下模板已包含该约束。

---

## Round 1: Independent Work (External Model Prompt)

```
你是一位资深专家。请针对以下任务，从指定视角给出你的专业分析和建议。

## 本任务的成功标准
{SUCCESS_CRITERIA}

注意：你的分析要服务于这个成功标准。如果你发现即使完成最好的分析也无法回答这个成功标准（例如缺少关键信息），请在"未决问题"中明确说出。

## 你的主责视角（优先关注，但不限于此）
{PRIMARY_FOCUS}

请优先深入分析上述视角相关的内容，但不要局限于此。鼓励你报告主责视角之外发现的任何重要观点——不要因为"这不是我的主责"而忽略它。

## 任务描述
{TASK_DESCRIPTION}

## 任务相关材料
{TASK_MATERIALS}

## 输出要求
请使用以下骨架输出（评审类）：

## 结论摘要
[2-3 句话概括核心判断]

## 发现
### [Critical|Major|Minor]-序号：标题
- **证据**：相关材料中的具体段落或位置
- **影响**：不修复会怎样
- **建议**：具体改法

（如果是设计/创作类任务，替换为：）

## 结论摘要
[2-3 句话概括方案核心]

## 方案
### 方案要点 N：标题
- **内容**：具体描述
- **决策理由**：为什么这样选

## 替代方案与权衡
## 未决问题
## 一句话结论

## 输出格式要求
- 只输出最终分析结果。禁止输出思考过程、命令日志、前言后记。
- 建议使用上方的输出骨架，但如果任务需要其他结构可以调整。
- 简洁优于冗长，但深度优于简洁。宁可分析透彻写 3000 字，也不要为了控制篇幅而省略重要发现。
- 请用中文输出。
```

## Quick Mode: 30-Second Devil's Advocate (External Model Prompt)

Used in quick mode between the lead model's Round 2 synthesis draft and final.md finalization. Prevents consensus bias from slipping through in 2-round mode. Keep prompt tight: one external model, ≤500 words response, 30-60 seconds.

```
这是一份快速综合草稿。请用 ≤500 字指出最致命的 1-2 个攻击点。不要做全面评审。

## 原始任务
{TASK_DESCRIPTION}

## 成功标准
{SUCCESS_CRITERIA}

## 快速综合草稿（来自主模型）
{SYNTHESIS_DRAFT}

## 你的任务
重点检查两类问题：
1. **共识偏见**：三方一致同意的点中，有哪个"所有人都没质疑的隐含前提"可能不成立？
2. **未考虑的边界场景**：用一个具体的用户情景反驳该方案——在什么场景下它会失效？

如果你找不到致命攻击点，写"无致命攻击点"，并简述你为什么认为草稿是扎实的。**不要**客气式肯定。

## 输出格式
- ≤500 字
- 格式：`## 攻击 1：...\n**证据**：...\n**后果**：...\n**建议**：...`
- 请用中文。
```

## Round 2: Cross-Validation (External Model Prompt)

Used in both quick mode (Round 2) and full mode (Round 2).

> **上下文传递**：Round 2 的外部模型输入是经过清洗的 Round 1 输出（已通过 `--output-last-message` 等方式去除元数据噪声）。仅当某个 Round 1 输出超过 5000 字时，主模型制作 digest 替代传递。

```
你是一位资深专家。在本轮交叉验证中，你需要阅读其他协作者的工作成果摘要，进行验证和补充。

## 你在 Round 1 的主要关注视角
{PRIMARY_FOCUS}

## 原始任务
{TASK_DESCRIPTION}

## 任务相关材料（如有必要回查）
{TASK_MATERIALS}

## 其他协作者的 Round 1 成果
{ROUND1_OUTPUTS}

## 任务要求
只输出以下四类内容，禁止复述 Round 1 中已有的观点：

1. **修正**：哪些 Round 1 观点你认为不准确？给出理由和修正建议。
2. **反对**：哪些你明确不同意？给出论据。
3. **补充**：阅读其他视角后，你发现了哪些 Round 1 中遗漏的重要内容？
4. **盲区**：综合所有 Round 1 成果后，有哪些重要维度被共同忽略了？

如果某一类没有内容，写"无"即可，不要凑数。

## 输出格式硬约束
- 只输出最终分析结果。禁止输出思考过程、命令日志、前言后记。
- 禁止复述或摘抄 Round 1 的内容。只写增量信息。
- 简洁优于冗长，但深度优于简洁。
- 请用中文输出。
```

## Round 2.5: Focused Rebuttal (External Model Prompt)

Only used in full mode when unresolved critical conflicts exist after Round 2.

```
你是一位资深专家。本轮聚焦于解决以下未解决的关键冲突。

## 原始任务
{TASK_DESCRIPTION}

## 待解决的关键冲突
{CONFLICT_POINTS}

## 各方立场摘要
{POSITIONS_DIGEST}

## 任务要求
对每个冲突点：
1. 明确你的立场（支持哪方，或提出第三条路径）
2. 给出具体论据（不是"我认为"，而是具体的技术/业务理由）
3. 如果你改变了 Round 1/2 中的立场，说明原因

## 输出格式硬约束
- 只针对列出的冲突点回应，不做全面重审。
- 请用中文输出。
```

## Round 3: Candidate Synthesis Structure

The Round 3 synthesis document must use "candidate" framing, not "final" framing:

```markdown
# 候选综合方案

> 本文档是候选综合，非最终方案。所有方案均待 Round 4 对抗性检验。

## 主题 N：[主题名称]

### 共识
[各方一致同意的点]

### 候选方案
[具体的方案/建议——使用"建议""候选"措辞，避免"最终""最优"]

### 待检验的假设
- 假设 1：[这个方案假设了 X 成立]
- 假设 2：[这个方案假设了 Y 不会发生]

### 未解冲突
- [如果某个分歧在 Round 2/2.5 中仍未解决，在此记录各方立场]

---

## 假设账本（汇总）

| 编号 | 假设 | 来源主题 | 可否验证 | 验证方式 |
|------|------|---------|---------|---------|
| H1 | ... | 主题 1 | 可 | ... |
| H2 | ... | 主题 3 | 不可（需运行时观察） | — |

## 遗留冲突清单

| 编号 | 冲突 | 各方立场 | 影响范围 |
|------|------|---------|---------|
| C1 | ... | A: ..., B: ... | ... |
```

## Independent Final Review (External Model Prompt)

Used after the lead model writes `final.md` (quick mode: after Round 2 synthesis; full mode: after Round 4 modifications). An external model reads the final.md draft and validates self-containment. If review fails, lead model must rework.

```
你是一位资深评审者。请**独立复核**以下 `final.md` 草稿，判断它是否真正自包含（"拿到就不用再问"）。

## 原始任务
{TASK_DESCRIPTION}

## 成功标准（final.md 必须能回答的问题）
{SUCCESS_CRITERIA}

## final.md 草稿
{FINAL_MD_DRAFT}

## 你的任务

逐项回答（不要绕圈）：

1. **TL;DR 充分性**：只读 §TL;DR 能否回答"任务/决策/下一步/取舍"四个问题？缺哪个？
2. **裁决可溯源**：每个决策的"来源"锚点是否真实指向前面的讨论？有无空引用或造引用？
3. **分歧表有效性**：§2 的表格是否反映了模型间的真实分歧，还是被主模型粉饰为"看似分歧但已解决"？
4. **行动项可执行**：§5 的 P0 动作是否可以直接交给执行者做，而不需要再翻阅其他文档？
5. **综合者偏差**：主模型在 R1 的立场是否被过度保留？有哪些少数意见被边缘化？给出具体证据。
6. **盲点**：final.md 遗漏了哪个重要视角或问题？

## 输出格式

```
## 评审结论
{{ pass | returned-for-rework }}

## 分项判断
1. TL;DR 充分性：{{ 通过 / 未通过 }} — {{ 原因 }}
2. 裁决可溯源：...
3. 分歧表有效性：...
4. 行动项可执行：...
5. 综合者偏差：...
6. 盲点：...

## 必须修正的问题（如 returned-for-rework）
- 问题 1：{{ 具体位置 + 怎么改 }}
- 问题 2：...

## 一句话结论
```

## 输出格式硬约束
- 不要客气式肯定。真有问题就说"未通过"。
- 不要输出思考过程。
- 请用中文输出。
```

## Round 4: Focused Attack (External Model Prompt)

> **关键设计**：每个模型执行全部四项检查，但通过"侧重分配"确保关键检查有足够深度。侧重项要求深入分析，非侧重项快速扫描即可。

### 魔鬼代言人版（侧重：回环检测 + 共识盲点）

```
你是一位"魔鬼代言人"——你的唯一任务是攻破下面的候选方案。

## 原始任务
{TASK_DESCRIPTION}

## Round 3 候选方案
{PROPOSED_SOLUTIONS}

## 强制检查清单
{ATTACK_CHECKLIST}

## 你的任务
对每个方案执行以下四项强制检查：

1. **【重点深入】同类问题回环检测**：这个方案是否重新引入了它试图解决的同类问题？
2. **【快速扫描】具体场景走查**：构造 1-2 个关键场景快速推演。
3. **【快速扫描】"去掉它试试"测试**：方案中的新组件是否真正必要？
4. **【重点深入】共识盲点检测**：前几轮讨论中有哪些被当成事实但实际上是可选择的隐含假设？

对每项检查给出：通过 / 未通过 / 存疑，附分析。重点项要深入分析，快速扫描项给出简要判断即可。

## 输出格式要求
- 只输出最终分析结果。禁止输出思考过程、命令日志、前言后记。
- 务必做一个严厉的、对抗性的评审者。不要客气。
- 深度优于简洁。宁可多写也不要遗漏重要发现。
- 请用中文输出。
```

### 压力测试版（侧重：场景走查 + 去掉它试试）

```
你是一位严格的方案评审者。请对候选方案进行压力测试。

## 原始任务
{TASK_DESCRIPTION}

## Round 3 候选方案
{PROPOSED_SOLUTIONS}

## 强制检查清单
{ATTACK_CHECKLIST}

## 你的任务
对每个方案执行以下四项强制检查：

1. **【快速扫描】同类问题回环检测**：这个方案是否重新引入了同类问题？给出简要判断。
2. **【重点深入】具体场景走查**：构造至少 3 个具体场景（正常路径、边界路径、中断/恢复路径），逐步推演寻找断裂点。
3. **【重点深入】"去掉它试试"测试**：列出方案中每个新组件，假设移除后评估影响。
4. **【快速扫描】共识盲点检测**：有哪些隐含假设值得质疑？给出简要判断。

对每项检查给出：通过 / 未通过 / 存疑，附分析。重点项要深入分析，快速扫描项给出简要判断即可。

## 输出格式要求
- 只输出最终分析结果。禁止输出思考过程、命令日志、前言后记。
- 场景必须具体到可推演状态，不要写抽象描述。
- 深度优于简洁。宁可多写也不要遗漏重要发现。
- 请用中文输出。
```
